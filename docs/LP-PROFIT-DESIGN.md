## 前提の裏取り（Fable が実物で確認した事実。ブリーフと食い違った点は明記）
- `index.html` のセクションIDは `#flow / #items / #fee / #photos / #trust / #weak / #faq / #contact / #legal-summary`。CTAは `[data-cta]` を `site.js` が一括で mailto（`LINE_URL` があれば LINE）に書き換える。mailto の本文は `site.js` 内の固定文字列で、config には無い。
- `site.js` は「ロジックを持たない」と README にあるが、実際は振込シミュレーターの計算（`x - x*FEE_RATE + bonus`）を持つ。レポートでも同じ式を使うので、この式を1か所に寄せる必要がある。
- LPには**紹介の約束がすでに存在する**: `#fee` の note「ご紹介があれば最低 14% まで下がります」、`legal.html` の「紹介併用時の下限 14%」、`docs/DESIGN.md` §2-2「紹介した人・された人の両方が次回 −3pt」。紹介の報酬は「現金」ではなく「手数料 −3pt」として公開済み。現金報酬の額が未決でも、既存の約束で紹介を運べる。
- `docs/DESIGN.md` §2-1 に目安額テンプレ（`{{LOW}}円〜{{HIGH}}円`／A. 送る（最低希望額）／B. 見送る）と発送ガイド（`{{SHIP_TO_ADDRESS}}`・同梱物3点）が確定文面としてある。レポートはこれの「ページ版」であり、文言を新たに作らない。
- `reviewcheck.jp/packages/core/src/utils/reportId.ts` の base64url(JSON) は TextEncoder 経由なので日本語が通る。`reviewcheck.jp/apps/web/lib/affiliateRef.ts` は `?ref=` を `/^[A-Za-z0-9_-]{1,32}$/` で検証し localStorage に30日保持。どちらも静的JSに数十行で移植できる。
- 会議の指標「レポート開封率 ≥30%」は追跡を足さない制約と矛盾するので計測不能。捨てる（F参照）。

## A. 理想の体験フロー

**目安額を受け取った人が「送る」に至るまで**

1. 写真6枚をメールで送る（既存 `[data-cta]` の mailto。変更なし）。
2. 24時間以内に返事のメールが届く（既存 §2-1 テンプレ）。メール本文に1行だけ増える: 「内訳と、ほかの売り方との比べ方はこちら → `https://bestprice-kaitori.com/report.html#…`」。メールだけで完結できる A/B の選択肢は残す（リンクを踏まない人のため）。
3. リンクを開くと1画面で次の順に見える:
   - 品物名／目安 `low〜high円`（何日時点の相場か）／お振込み目安（初回20%・モニター枠が残っていれば15%も）
   - **3行の比べ表**（業者の競り＝うち／自分でフリマ／近くの買取店 × 手取り・日数・手間）。うちが不利なら不利と書いてある。担当者が「この品はフリマの方が多く残る可能性あり」と判断した品には、その1行が出る。
   - **「この目安で送る」ボタン**（表の直下）。押すとメールが開き、品物・目安・最低希望額の記入欄・レポートURLが入っている。書くのは最低希望額だけ。
   - その下に送り先・同梱物3点（既存 `SHIP_TO` と §2-1 発送ガイドの文面）。「ご連絡→発送」の順で、返事を待たず当日発送できる。往復1回（最大24時間）が消える。
   - 「見送る場合は返事不要。費用はかかりません」。
4. 荷物到着→開封動画→出品→落札→明細と振込（既存の約束どおり。変更なし）。

**送った人が次の人を連れてくるまで（第2弾。初回振込が1件出た日から）**

5. 振込完了メールに紹介URL `https://bestprice-kaitori.com/?ref=BP-XXXX` と、公開済みの約束（紹介した人・された人の両方が次回 −3pt、下限14%）を書く。現金の額は書かない（未決）。
6. 紹介された人がLPを開く→ `site.js` が `?ref` を保存→写真メールの本文末尾に「■ 紹介コード（消さないでください）: BP-XXXX」が自動で入る。
7. 受信メールを週1で数えて、紹介経由の依頼数を台帳シートに書く。抜けは紹介者本人からの申告で拾う（C-4）。

## C. 具体機構

### C-1. payload スキーマ（v1・個人情報の項目を持たない）
```
{ "v": 1,
  "item": "iPhone 13 128GB SIMフリー",   // 1〜60文字
  "low": 30000, "high": 38000,           // 整数、0 < low ≤ high ≤ 10,000,000
  "d": "2026-09-10",                     // 目安を出した日（YYYY-MM-DD）
  "diy": false,                          // 担当者の判断: フリマの方が多く残る可能性
  "note": "バッテリー最大容量が85未満だと下がります", // 任意・120文字まで
  "sample": false }                      // true なら見本バナー
```
- URL: `report.html#` + base64url(JSON)。`reportId.ts` の encode/decode をそのまま移植（TextEncoder→btoa→`+/=` 置換）。JSON 200バイト前後→URL 300文字弱。メール本文に収まる。
- 検証: `v===1`、型・範囲・文字数を全部見る。1つでも外れたら `null`＝「見つかりません」画面（`#rp-notfound`）と「写真を送り直す（無料）」→ `index.html#contact`。氏名・住所・口座の項目はスキーマに無い＝作成ツールにも欄が無い（構造で防ぐ）。
- 未知のキーは無視（将来 `ref` を足しても v1 のまま読める）。

描画は全部 `textContent`。`innerHTML` を使わない。`?` のクエリは一切読まない。`<meta name="robots" content="noindex">`。

### C-3. 3行の比べ表（文言確定・外部の数字は入れない）
| 売り方 | 手取り | 日数 | 手間 |
|---|---|---|---|
| 業者の競り（うち・お預かり販売） | 落札額 − 手数料（全部込み `FEE_RATE`）。この品なら `#rp-net` の範囲 | 発送から通常2〜3週間 | 写真6枚と、宅配便1回 |
| 自分でフリマに出す | 売値 − 各サービスの手数料 − 送料。うちより多く残ることがあります | 売れるまで。数日のことも、数か月のことも | 撮影・出品・質問への返事・値下げ交渉・梱包・発送・受取後の対応をすべてご自身で |
| 近くの買取店 | その場で提示される買取額（店ごとに違います） | 当日 | 持ち込み。比べるなら複数店へ |

表の直下が `#rp-send`。表の前後に説明文を足さない（情報を増やして満足しない）。

### C-4. mailto 本文の形（`#rp-send`）
```
subject: 発送します【{item}】
body:
【発送のご連絡】
■ 品物: {item}
■ 目安: {low}円〜{high}円（{d}時点）
■ 最低希望額: ______円（未記入なら {low}円）
■ 発送予定日: 
■ 追跡番号: （発送後にお送りください）
■ レポート: {このページのURL}
```
- レポートURLを本文に入れるのは、受信側で「どの目安に対する発送か」を追跡なしで突き合わせるため（URL自体がIDになる）。
- 第2弾で `?ref` を運ぶときは、写真査定 mailto（`site.js`）とこの本文の両方の末尾に「■ 紹介コード（消さないでください）: {code}」を足す。ref の保持は `affiliateRef.ts` の移植: localStorage キー `bp_ref`（新規）、TTL 30日、last-click、正規表現 `/^[A-Za-z0-9_-]{1,32}$/`、URL優先→保存値。付与は `new URL()`＋`searchParams` ではなく本文の1行（mailto なので）。値をDOMに書かない。
- 抜けに気づく仕組み（第2弾）: 振込完了メールの紹介案内に「紹介した方の発送が確認できたらお知らせします。2週間たっても連絡が無いときは、その方の苗字だけ教えてください」と書く。紹介者は10人以内なので、人の申告と受信メールの突き合わせで十分。自動集計は作らない。

### C-5. `tools/report-maker.html`
- 入力: 品物名／low／high／日付（既定＝今日）／DIY チェック／一言（任意）／見本チェック。
- 出力: ①レポートURL ②返事メール本文（§2-1 目安額テンプレに `{{LOW_NET}}` 等を `BP_calc` で埋め、末尾にURLの1行を足したもの）。それぞれコピーボタン。
- ガード: `high < MIN_ESTIMATE` なら「受付できない額です」で作らせない。自由記述（品物名・一言）に禁句（D の正規表現）が含まれたら赤く出して作らせない。
- 氏名・住所・口座の欄を作らない。

### C-6. `docs/DESIGN.md` §2-1 の変更（文書）
目安額テンプレの「▼ 次のどちらか」の前に1行: 「内訳と、ほかの売り方との比べ方 → {{REPORT_URL}}」。それ以外は変えない。

## D. 数字と約束の扱い

**書ける（出典がある）**
- 自社の価格（`config.js` の値を `data-cfg-pct / data-cfg-yen` で表示）。手数料の「20%」は価格表示であり、禁句リストの「%」（確率・割合の断定）とは別。ただし「9割の方が」のような割合の%は書かない。
- 既存の約束（LP・legal.html にある文言をそのまま再掲）。新しい約束を増やさない。
- 目安額: 人が直近の落札相場から出し、日付を付け、「確定額ではありません」を必ず並記。ページは payload を表示するだけで値段を決めない。
- 「始めたばかりで実績の数字はまだ出せません」（`.honest` の文言）。レポートにも同文を置いてよい。
- 見本: `sample:true` バナー付きに限る。見本の数字はシミュレーターの既定値（30,000円）と同程度の「仮の数字」と明記。

**書けない**
- 実例カード（発送0件）／開封率・成約率・返金率などの率／他社の手数料の数字（メルカリ等。古くなる・「他社より」に見える）／「限定」「今だけ」「先着」を理由なしに使うこと／紹介料の額（未決）／「必ず」「確実」「保証」「高額買取」「業界最高値」「誰でも稼げる」／「可能性が高い」（禁句。「可能性があります」は可）。
- DIY 行は「多くなる可能性があります」で止める。「フリマの方が高い」と断定しない。

**紹介（第2弾）の文言**
- 報酬は公開済みの「紹介した人・された人の両方が次回 −3pt（下限14%）」だけ。現金は書かない。
- 上限は「手で確認・手で反映しているため、いまは紹介者10名までにしています（残り N 名）」と理由付きで、残り数を見せる（上限到達の disabled は悪手）。
- ステマ規制: 紹介案内に「知人に薦めるときは、紹介した側にも特典があることを伝えてください」を入れる。
- 現金報酬を足す日が来たら `REFERRAL_REWARD_YEN`（新規・今回は入れない）の1変数と、条件・締め日・支払方法の文章を legal.html に先に公開してから。

**禁句の機械チェック（0円）**: `ai-health-check.link/src/kenshin/banned.ts` の断定・煽り・比較・時限の行を抜いた正規表現を `tools/report-maker.html` に埋め、公開前に `index.html / report.html / tools/report-maker.html` へ同じ正規表現で grep（`node -e` の1行でよい）。CIは作らない。目視の代替にはならない。

## E. MVP（1つだけ）

**作るもの: 売り先くらべレポート**（`report.html` ＋ `report-codec.js` ＋ `tools/report-maker.html` ＋ `index.html` の `#flow` 手順2にリンク1本 ＋ `config.js` に `SAMPLE_REPORT_ENABLED` ＋ `site.js` の `BP_calc` 切り出しと `[data-sample-report]` 切替 ＋ `docs/DESIGN.md` §2-1 の1行）。費用0円。実装は1日、残りは運用。

**なぜこれ1つか**: 財布が開く瞬間は「目安を見て送ると決める」ところ。ここを「メールを読んで返信を書く」から「表を見てボタンを押す（または当日発送する）」に変え、往復1回を消す。紹介は紹介者がまだ0人なので、今作っても測る相手がいない。

**数える数字（週1・月曜・受信トレイと荷物から手で数え、既存の落札額シートに「週次」タブを足す）**
- P: 写真メール数
- R: レポート発行数（＝目安を返した数。送信済みメールで数える）
- S: 発送件数（荷物の到着で数える。唯一の主指標）

**判定（期間: レポート10通発行まで、または4週間の早い方）**
- 続行: R=10 で S ≥ 3
- 文面を替える（比べ表の書き方・ボタン文言・送り先の位置のどれか1つ）: R=10 で S ≤ 1
- 評価不能: 4週間で R < 5 → この案の問題ではなく写真が来ていない。LPを触らず集客（`docs/DESIGN.md` §6 ジモティー・X）に戻る
- 全体の撤退線は `docs/DESIGN.md` 判断#9（30日で発送0→文面替え、60日で発送3件未満→撤退）のまま。上書きしない。

**第2弾の着手条件**: 初回振込が1件完了した日。中身は C-4 の ref 保持と本文1行、FAQ に「紹介について」1項目（既存の −3pt を再掲）、`REFERRAL_ENABLED`（新規）で表示切替。半日で入る。

## F. 捨てた案と理由

| 案 | 出所 | 却下理由 |
|---|---|---|

## G. 地雷と回避策（実装者が踏みそうな順）

1. **`[data-cta]` の一括書き換え**: `report.html` の送るボタンに `data-cta` を付けると `site.js` が写真査定の mailto に上書きする。`#rp-send` は独自IDで、`data-cta` を付けない。ヘッダーCTAも置かない。
2. **`btoa` に日本語を渡すと例外**: 必ず `TextEncoder` でUTF-8バイト列にしてから base64。decode も `TextDecoder`。`reportId.ts` の順序をそのまま写す。
3. **`?` と `#` の取り違え**: payload は `location.hash`（先頭の `#` を除く）。クエリは読まない。hash はサーバーに送られない＝ログにも残らない、が設計意図。
4. **反射型XSS**: payload 由来の文字列は `textContent` だけ。`innerHTML`・テンプレートリテラルでのHTML組み立て禁止。文字数上限（item 60・note 120）を decode 時に落とす。
5. **計算式の二重管理**: `site.js` の `render()` と `report.html` で式を別々に書くと、いつかずれる。`window.BP_calc(x, rate)` を `site.js` に置き、両方がそれを呼ぶ。切り出し後にシミュレーターの表示が変わっていないことを既定値30,000円で目視。
6. **mailto 本文の長さ**: メールクライアントによって本文は2,000文字前後で切れる。C-4 の本文は300文字以内に収め、改行は `encodeURIComponent` で `%0A` にする。iOS メール・Gmail アプリの両方で開いて本文が全部入っていることを実機で見る。
7. **メール内リンクの hash 落ち**: Gmail アプリ等のアプリ内ブラウザで `#` 以降が残るか、実際に自分宛てに返事メールを送って踏む。落ちる環境が見つかったら `?r=` に切り替える（その場合はログに残る前提で個人情報ゼロのスキーマが効く）。
8. **見本に本物らしい数字**: `sample:true` を付け忘れると「実績のような数字」がLPからリンクされる。作成ツールの見本チェックで生成し、`#rp-sample-banner` が出ることをLPのリンクから実際に開いて確認。
9. **モニター率の食い違い**: レポートは表示時点の `MONITOR_FILLED` で15%行を出す。荷物が到着するたびに `MONITOR_FILLED` を更新しないと、枠が無いのに15%が見える（LPも同じ）。運用ルールに「到着当日に更新」を1行足す。
10. **偽造URL**: 静的なので署名できず、誰でも作成ツールでレポートURLを作れる。実害は「うちが出したように見える目安」を第三者が見せること。レポートに「同じ内容をメールでもお送りしています。食い違う場合はメールが正です」を1行置く。作成ツールは noindex・リンクなし。
11. **禁句の混入経路は自由記述**: HTMLの固定文言は grep で止まるが、担当者が作成ツールに書く「一言」は止まらない。C-5 のガードを必ず入れ、「必ず」「確実」「可能性が高い」「限定」を弾く。
12. **`README.md` の「site.js はロジックを持たない」**: README と実物が既にずれている。`BP_calc` を足したら README の表の1行を「計算（振込目安）だけ持つ」に直す。
13. **「編集した＝反映された」ではない**: push 後に本番の `report.html#…` を作成ツールの出力そのままでスマホから開き、送るボタンでメールが起動するところまで見てから完了にする。
14. **1つ直したら測ってから次**: 判定期間中に `#flow` 以外のLP文言を触らない。第2弾（ref）は初回振込1件が出るまで着手しない。
